## 1. 先懂这些词（零基础）

### 1.1 解决方案 vs 项目


| 词                         | 通俗理解                                                      |
| ------------------------- | --------------------------------------------------------- |
| **解决方案** `SpiritDesk.sln` | 一个「工作区」，里面装了多个 C# 项目，Visual Studio / `dotnet build` 一次编全部 |
| **项目** `.csproj`          | 一个可编译单元：要么编成 **dll 类库**，要么编成 **网站**，要么编成 **exe 桌面程序**     |


### 1.2 WPF 是什么？

- **WPF** = Windows Presentation Foundation，微软做 **Windows 桌面窗口界面** 的技术（按钮、窗口、菜单那种原生桌面 UI）。
- 本项目的 **SpiritDesk.Shell** 就是 WPF 程序：有主窗口、有桌面浮球。
- 文件后缀：`.xaml`（界面长什么样，类似 XML）、`.xaml.cs`（界面背后的 C# 逻辑）。

**和网页的关系**：Shell 不重复做一套业务页面，主窗口里嵌 **WebView2**（一个内置的 Chromium 浏览器），去显示 SpiritDesk.Web 的网页。

### 1.3 Razor Pages 是什么？

SpiritDesk 的网页（登录、聊天、设置等）用 **ASP.NET Core Razor Pages** 做。可以分三层理解：

#### ① Razor：HTML 里能写 C# 的模板

- 文件后缀 `**.cshtml`** = **C# + HTML** 混写（Razor 视图）。
- 在 HTML 里用 `@` 插入 C#，例如 `@Model.Nickname`、`<form method="post">`。
- 浏览器最终只看到 **HTML**；`@` 开头的代码在服务器上执行完才被“填进”页面。

#### ② 两种文件各干什么（不要和 `.cs` 搞混）


| 后缀               | 全称含义                        | 里面写什么                       | 类比                   |
| ---------------- | --------------------------- | --------------------------- | -------------------- |
| `**.cshtml`**    | Razor 页面（视图）                | 标签、CSS 类名、表单、`@Model.xxx`   | 网页的“皮”——长什么样         |
| `**.cshtml.cs**` | 该页面的 **PageModel**（仍是 C# 类） | `OnGet` / `OnPost`、查库、校验、跳转 | 网页的“脑”——点进来、提交表单时干什么 |


注意：`**.cshtml.cs` 不是两个扩展名**，而是一个完整后缀，表示“这个 `.cshtml` 专属的后台 C# 文件”。编译后它和任意 `.cs` 一样进 DLL，只是命名约定让你一眼看出“属于哪一页”。

#### ③ “一对文件”是什么意思？

**Razor Pages 的约定**：`Pages` 目录里，**同一个页面名**占两个文件，框架自动把它们绑在一起。

以聊天页为例：


| 文件路径                   | 类名 / 作用                                      |
| ---------------------- | -------------------------------------------- |
| `Pages/Chat.cshtml`    | 顶部写 `@model ChatModel`，下面用 `@Model` 显示数据     |
| `Pages/Chat.cshtml.cs` | `public class ChatModel : PageModel { ... }` |


规则小结：

- 两个文件 **主文件名必须相同**（`Chat` + `Chat`）。
- `.cshtml` 里的 `@model` 必须指向 `.cshtml.cs` 里的那个类（`ChatModel`）。
- 类名习惯叫 `**{页面名}Model`**（`Chat` → `ChatModel`，`Login` → `LoginModel`）。
- 子文件夹也适用：`Pages/Spirits/Select.cshtml` + `Select.cshtml.cs` → URL 是 `/Spirits/Select`，类名是 `SelectModel`。

只有 `.cshtml`、没有配套的 `.cshtml.cs` 也可以（纯静态展示）；但本项目业务页几乎都是 **一对都有**。

#### ④ 用户打开 `/Chat` 时发生了什么（顺序）

```text
浏览器请求 GET /Chat
    ↓
ASP.NET Core 根据路径找到 Pages/Chat.cshtml + Chat.cshtml.cs
    ↓
实例化 ChatModel，调用 OnGet()（读会话、查数据库、给属性赋值）
    ↓
把 ChatModel 作为 Model 传给 Chat.cshtml，执行其中的 Razor（@Model.xxx）
    ↓
生成完整 HTML 返回浏览器
```

用户点“发送”提交表单时，走 `**OnPost()**`（或 `OnPostXXX()`），同样在 `.cshtml.cs` 里写；处理完要么 `return Page()` 再画一遍页面，要么 `RedirectToPage(...)` 跳转。

**和 WPF 对照**：`.cshtml` ≈ `.xaml`（界面），`.cshtml.cs` ≈ `.xaml.cs`（逻辑）；只是网页在服务器渲染，不是桌面窗口。

#### ⑤ 是不是 SSR？和 React/Vue 有啥区别？

**是 SSR（服务端渲染）。**

| 方式 | 谁生成最终 HTML | 本项目 |
|------|-----------------|--------|
| **SSR** | 服务器执行 `.cshtml` + C#，拼好 HTML 再响应 | ✅ **就是这种** |
| **CSR / SPA** | 浏览器下载 JS，再由 JS 请求 API 画界面 | ❌ 没有 React/Vue 工程 |

- 用户访问 `/Index` 时，服务器先跑 `Index.cshtml.cs` 的 `OnGet`，查 SQLite，再把数据填进 `Index.cshtml` 的 `@Model.xxx`，**返回的已是带昵称、任务列表的完整 HTML**。
- `wwwroot` 里的 CSS/JS 是**静态文件**，浏览器第二次请求加载；它们不负责「拼页面数据」。
- 详见：[10-SpiritDesk.Web项目与cshtml详解.md](./10-SpiritDesk.Web项目与cshtml详解.md)、[basic/08-wwwroot与静态资源详解.md](./basic/08-wwwroot与静态资源详解.md)。

#### ⑥ 和 MVC 的对比（本项目为什么用 Razor Pages）


|      | **Razor Pages（本项目）**                       | **MVC（常见另一种写法）**                        |
| ---- | ------------------------------------------ | --------------------------------------- |
| 入口   | `Pages/某页.cshtml.cs` 里的 `OnGet` / `OnPost` | `Controllers/某Controller.cs`            |
| 界面   | `Pages/某页.cshtml`                          | `Views/某页.cshtml`                       |
| 对应关系 | **一页 = 一对文件**，URL 跟 `Pages` 下路径走           | **一个 Controller 管多页**，路由在 Controller 上配 |


本项目 **没有** `Controllers/` 文件夹；登录、注册、聊天等逻辑入口都在 `**Pages/**/*.cshtml.cs`**。找“登录提交后干了什么”→ 打开 `Login.cshtml.cs`，不要只在 `Login.cshtml` 里找。

**和 MVC / MVVM 的关系**：Web 是 **Razor Pages**（分页 MVC 思想，不是经典 Controller+MVC，也不是 MVVM）。`Models/*ViewModel` 是展示 DTO，不是 WPF 绑定。详见 [basic/09-MVC还是MVVM我们用的哪种.md](./basic/09-MVC还是MVVM我们用的哪种.md)。

### 1.4 EF Core 是什么？

- **EF** = Entity Framework，**.NET 里操作数据库的工具**。
- **EF Core** = 跨平台新版 EF。
- 你定义 C# 类（在 `SpiritDesk.Core/Entities`）→ 在 `SpiritDeskDbContext` 里声明「这些类对应哪些表」→ 运行时 EF 帮你 **增删改查 SQLite**，大部分时候不用手写 SQL。

**SQLite**：数据库就是一个文件（例如 `data/spiritdesk.db`），适合课程演示，拷走文件就等于拷走数据。

**零基础专篇**（含 ORM、DbContext、本项目表对照、答辩答法）：[basic/13-EF是什么详解.md](./basic/13-EF是什么详解.md)。

### 1.5 API 是什么？（在本项目里）

- **API** 这里指：除了给人看的 **网页**，程序还给 **别的程序** 提供一些 **HTTP 地址**（返回 JSON，不是整页 HTML）。
- 例如桌面浮球问：「当前精灵是谁？」→ `GET /api/companion/current`。
- 代码写在 `SpiritDeskWebHost.cs` 里，用 `app.MapGet` / `app.MapPost`（叫 **Minimal API** 写法）。

```
人点网页  →  Razor Page  →  返回 HTML
浮球/脚本  →  /api/...     →  返回 JSON
```

### 1.6 其它常见缩写


| 词                   | 含义                                                           |
| ------------------- | ------------------------------------------------------------ |
| **DI**              | 依赖注入：在 `SpiritDeskWebHost` 里注册 `SpiritDeskService`，页面里自动拿到实例 |
| **DTO / ViewModel** | 给页面或 API 用的「展示用数据结构」，在 `Models/`                             |
| **wwwroot**         | 网站静态文件根目录，URL `/css/site.css` 对应磁盘 `wwwroot/css/site.css`    |
| **NuGet**           | C# 的包管理器，`PackageReference` 下载 EF、WebView2 等第三方库             |

## 2. Core / Web / Shell 分别是什么

用「开饭店」类比（只为记忆，不是严格架构术语）：


| 项目                   | 类型          | 类比                    | 在本项目里真正干什么                                         |
| -------------------- | ----------- | --------------------- | -------------------------------------------------- |
| **SpiritDesk.Core**  | 类库 dll      | **菜单与食材标准**（定义菜名、字段）  | 只有 `Entities` + `SpiritIds`，**没有** 网页、**没有** 数据库连接 |
| **SpiritDesk.Web**   | 网站 exe      | **厨房 + 大堂**（做菜、上菜、收银） | Razor 页面、EF、SQLite、聊天/任务业务、给浮球用的 API               |
| **SpiritDesk.Shell** | Windows exe | **外卖窗口 + 门口吉祥物**      | WPF 窗口、WebView2 打开 Web；浮球调 Web 的 API               |


**一句话**：Core 定义数据长什么样；Web 实现全部业务；Shell 是 Windows 外壳，业务仍靠 Web（本地子进程或云端网址）。

## 3. 项目依赖：谁引用谁

### 3.1 csproj 里的引用（编译期）

```
SpiritDesk.Core          （不引用其它本项目）

SpiritDesk.Web    ──引用──►  SpiritDesk.Core

SpiritDesk.Shell  ──引用──►  SpiritDesk.Core
                  ──引用──►  SpiritDesk.Web   （保证 Web 先编译；本地启动时找到 Web.dll）
```

对应文件：

- `SpiritDesk.Web.csproj` → `<ProjectReference Include="..\SpiritDesk.Core\..." />`
- `SpiritDesk.Shell.csproj` → 同时引用 Core 和 Web

**Shell 为什么还引用 Core？**  
浮球里直接用 `SpiritIds.Light` 等常量拼内置菜单，和 Web 保持一致，不必手写字符串。

**Shell 为什么引用 Web？**  
不是为了在 Shell 里写网页逻辑，而是：

1. `dotnet build` 时 Web 一定是最新的；
2. `MainWindow` 启动子进程时知道 Web 编译输出路径。

### 3.2 运行期（进程级）

```
┌─────────────────────────────────────────────────────────┐
│  SpiritDesk.Shell.exe (WPF)                              │
│    MainWindow + WebView2  ──HTTP──►  SpiritDesk.Web      │
│    CompanionBubbleWindow ──HTTP──►  /api/companion/...   │
└─────────────────────────────────────────────────────────┘
                              │
                              ▼
                    SpiritDesk.Web 进程
                      ├─ Razor Pages
                      ├─ EF Core ──► SQLite 文件
                      └─ LlmReplyService ──► 豆包 API（.env）
```

Shell **不直接连 SQLite**；换精灵、读心情都是 **HTTP 找 Web**。

| 标记  | 含义                                                | 你要不要动               |
| --- | ------------------------------------------------- | ------------------- |
| 🟢  | **团队自写业务**：需求、精灵、任务、登录等核心逻辑                       | 常改                  |
| 🔵  | **模板生成后已大改**：最初 `dotnet new` 有，但内容已是 SpiritDesk 的 | 常改                  |

| ⚪   | **模板/第三方自带**：Bootstrap、jQuery 等                   | 一般不改                |
| 🔴  | **编译/发布生成**：`bin/` `obj/` `artifacts/`            | **不要提交 Git**，可删了再生成 |
| 🟣  | **运行后生成**：SQLite、`data/keys/`、用户 AppData 配置       | 不在仓库里               |


**常见命令与生成物**：


| 命令                                   | 会生成什么                                             |
| ------------------------------------ | ------------------------------------------------- |
| `dotnet new web`                     | 最初 Web 骨架：`Program.cs`、`Pages/` 部分页、`wwwroot/lib` |
| `dotnet new classlib`                | Core 类库骨架（本项目 Entities 为后续自加）                     |
| `dotnet new wpf`                     | Shell 骨架：`App.xaml`、`MainWindow.xaml`             |
| `dotnet build`                       | 各项目下 `bin/`、`obj/`                                |
| `dotnet publish` / `publish-web.ps1` | `artifacts/spiritdesk-web-publish/`               |
| `dotnet run` Web                     | `data/spiritdesk.db` 等                            |
| `dotnet run` Shell                   | `%AppData%/SpiritDesk/` 下浮球设置 JSON                |

## 7. SpiritDesk.Core：逐文件说明

Core **没有** `Program.cs`，编译成 `SpiritDesk.Core.dll` 给 Web（和 Shell 常量）引用。


| 文件                             | 作用                                              | 谁写入库 |
| ------------------------------ | ----------------------------------------------- | ---- |
| `SpiritDesk.Core.csproj`       | 声明 net9.0 类库                                    | 🟡   |
| `Constants/SpiritIds.cs`       | 五精灵 ID：`light` `water` `air` `soil` `nutrition` | 🟢   |
| `Entities/UserProfile.cs`      | 用户档案：绑定登录账号，保存昵称、当前精灵、心情、亲密度、等级、金币                 | 🟢   |
| `Entities/SpiritDefinition.cs` | 精灵元数据：名字、称号、加成类型等                               | 🟢   |
| `Entities/TaskItem.cs`         | 待办：所属档案、标题、完成状态、截止时间等                           | 🟢   |
| `Entities/ChatMessage.cs`      | 聊天记录：所属档案、角色 user/spirit、内容、时间                  | 🟢   |
| `Entities/DailyActionLog.cs`   | 每日互动次数：按档案记录签到、投喂等防刷                            | 🟢   |
| `Entities/WebAccount.cs`       | 登录账号：用户名、密码哈希                                   | 🟢   |


**为什么单独一层 Core？**  
Web 的 EF、页面、Shell 的浮球菜单都要用同一套「用户、任务、精灵 ID」。放在 Core 里 **只定义形状**，避免复制粘贴两份类定义。

**Core 里没有什么？**  
没有 `DbContext`、没有 `Login.cshtml`、没有 API——那些都在 Web。

4. WebView2 打开 `http://127.0.0.1:端口`；
5. 再显示 `CompanionBubbleWindow`。

## 11. 一条用户操作怎么穿过各层

**例子：在聊天页发一句话**

```
1. 浏览器 POST /Chat
2. Chat.cshtml.cs（Razor PageModel）收到表单
3. 调用 SpiritDeskService + LlmReplyService
4. SpiritDeskService 通过 SpiritDeskDbContext（EF）写入 ChatMessage 表（SQLite）
5. LlmReplyService 可选请求豆包 API（读 .env）
6. 返回 Chat.cshtml 渲染后的 HTML
```

**例子：桌面浮球右键换「嘻嘻滴」**

```
1. CompanionBubbleWindow（WPF）菜单点击
2. HttpClient POST /api/companion/select-spirit  JSON { spiritId: "water" }
3. SpiritDeskWebHost 里 Minimal API 处理
4. SpiritDeskService 更新 UserProfile.CurrentSpiritId（EF 写库）
5. 浮球再 GET /api/companion/current 刷新头像和台词
```
