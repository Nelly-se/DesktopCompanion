# 01 - 中间件基础知识

> 本篇只讲通用概念，不涉及 SpiritDesk 具体代码。  
> 看完再读 [02-本项目中间件管道详解.md](./02-本项目中间件管道详解.md)。

---

## 0. 一句话（先背）

**中间件（Middleware）** 是 Web 服务器处理每一个 HTTP 请求时，按顺序经过的一层一层“检查站”。

每个检查站可以：

- 检查请求（例如有没有登录 Cookie）
- 修改请求或响应
- 直接返回结果（不再往后走）
- 调用下一个检查站（`next`）

---

## 1. 用生活例子理解

把一次 HTTP 请求想成“访客进大楼”：

```text
访客（浏览器请求）
  ↓
保安登记（路由）
  ↓
前台查证件（认证）
  ↓
门禁刷卡（授权）
  ↓
到达目标办公室（页面 / API）
  ↓
带着结果离开（响应返回）
```

每一道门就是一个中间件。  
访客必须按大楼规定的顺序过门，不能跳过。

---

## 2. 什么是“管道”（Pipeline）？

多个中间件首尾相接，就叫 **中间件管道** 或 **请求管道**。

```text
请求进入
  → 中间件 A
  → 中间件 B
  → 中间件 C
  → 终点（Razor 页面 / API 处理函数）
  → 中间件 C（响应往回走）
  → 中间件 B
  → 中间件 A
  → 响应返回浏览器
```

要点：

| 要点 | 说明 |
|------|------|
| 有顺序 | 先注册的先执行（进入时）；响应返回时顺序相反 |
| 可短路 | 某层可以直接返回 404、302 跳转、401，不再调用后面 |
| 共享上下文 | 同一请求里，后面的中间件能看到前面放进去的信息（如当前用户） |

## 3. ASP.NET Core 里怎么写中间件？

常见两种写法：

### 3.1 `app.UseXxx()` — 注册中间件

```csharp
app.UseRouting();
app.UseStaticFiles();
app.UseAuthentication();
app.UseAuthorization();
```

`Use` 开头的方法，一般表示往管道里**加一层**。

### 3.2 `app.MapXxx()` — 注册终点（端点）

```csharp
app.MapRazorPages();
app.MapGet("/api/hello", () => "Hi");
```

`Map` 表示：**匹配到某路径时，由这里的代码处理请求**。

可以粗略理解：

| 写法 | 更像什么 |
|------|----------|
| `Use*` | 过道上的检查站 |
| `Map*` | 最后一间办公室（端点） |

---

## 4. `Use` 和 `Map` 的区别

| 对比项 | `Use` 中间件 | `Map` 端点 |
|--------|--------------|------------|
| 是否匹配特定路径 | 通常每条请求都会经过（除非内部判断跳过） | 只有路径匹配才执行 |
| 典型作用 | 认证、静态文件、异常处理、路由 | Razor 页面、REST API |
| 能否调用 `next` | 可以决定是否交给下一层 | 匹配后由端点处理，一般不再往后 |

例子：

- `UseStaticFiles()`：如果请求的是 `/css/site.css`，可能在这里就直接返回文件。
- `MapRazorPages()`：如果请求是 `/Index`，由 Razor 页面处理。

---

## 5. 为什么顺序很重要？

顺序错了，功能会异常。

常见规则（ASP.NET Core）：

```text
UseExceptionHandler   ← 尽量靠前，兜住后面抛出的异常
UseRouting            ← 先知道“要去哪”
UseAuthentication     ← 先认人（你是谁）
UseAuthorization      ← 再授权（你能不能进）
MapRazorPages / MapGet ← 最后执行业务
```

如果 **授权在认证前面**：

> 还没验证 Cookie，就去判断“有没有权限”，逻辑会乱。

如果 **静态文件放在很后面**：

> 可能先走了认证、页面逻辑，效率差，甚至行为不符合预期。

## 6. 中间件 vs `builder.Services`（DI）

新手容易混：

| 概念 | 阶段 | 作用 |
|------|------|------|
| `builder.Services.AddXxx()` | **启动时注册服务** | 告诉容器“有哪些类可以注入”，例如 `SpiritDeskService`、认证服务 |
| `app.UseXxx()` | **启动时组装管道** | 告诉运行时“每个请求按什么顺序处理” |

例子：

```csharp
builder.Services.AddAuthentication(...);  // 注册认证能力
app.UseAuthentication();                  // 启用认证中间件
```

- `AddAuthentication`：**准备工具**
- `UseAuthentication`：**在管道里真正使用工具**

---

## 7. 中间件 vs 过滤器（Filter）

| 对比 | 中间件 | 过滤器（如 Razor Page Filter） |
|------|--------|--------------------------------|
| 作用范围 | 整个应用、所有请求 |  mainly MVC/Razor 相关 |
| 能否处理静态文件请求 | 能 | 一般不参与 |
| 认证授权 | 常在这里 | 也可配合 |
| 本项目 | **主要用中间件做认证/授权/静态文件** | Razor Pages 用得少 |

SpiritDesk 答辩时重点讲 **中间件管道** 即可。

## 8. 常见内置中间件（认识名字）

| 方法 | 作用 |
|------|------|
| `UseExceptionHandler` | 未捕获异常时转到错误页 |
| `UseHttpsRedirection` | HTTP 跳 HTTPS（本项目本地常不用） |
| `UseStaticFiles` | 提供 `wwwroot` 下 CSS/JS/图片 |
| `UseRouting` | 路由匹配，决定端点 |
| `UseAuthentication` | 解析 Cookie / Token，设置当前用户 |
| `UseAuthorization` | 检查 `[Authorize]`、页面门禁 |
| `UseCors` | 跨域（本项目本地同源为主） |

---

## 9. “短路”是什么意思？

某层中间件决定**不再调用下一层**，直接返回响应，叫 **短路（short-circuit）**。

例子：

1. `UseStaticFiles` 发现 `/css/site.css` 存在 → 直接返回文件 → 短路。
2. `UseAuthentication` 发现 Cookie 无效 → 可能配合授权返回 302 到 `/Login` → 短路。
3. `UseExceptionHandler` 捕获异常 → 返回 `/Error` 页面 → 短路。

## 10. 老师可能怎么问

**问：什么是中间件？**  
> 中间件是 ASP.NET Core 处理 HTTP 请求时按顺序执行的一组组件，组成请求管道；每个中间件可以处理请求、修改响应或决定是否继续交给下一层。

**问：中间件管道是什么？**  
> 多个 `Use` 注册的中间件按顺序连接成的处理链，请求从前往后、响应从后往前。

**问：Use 和 Map 有什么区别？**  
> `Use` 一般是管道上的通用处理层；`Map` 是路径匹配后的终点，例如 Razor 页面或 API。

**问：为什么认证要在授权前面？**  
> 要先通过认证知道用户是谁，授权才能判断该用户有没有权限访问资源。
