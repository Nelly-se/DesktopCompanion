# 02 - 本项目中间件管道详解

> 本篇对照 `src/SpiritDesk.Web/SpiritDeskWebHost.cs`，逐段说明 SpiritDesk **用了哪些中间件、顺序、和登录门禁的关系**。

---

## 0. 入口在哪里？

| 文件 | 做什么 |
|------|--------|
| `Program.cs` | `SpiritDeskWebHost.Build(args)` → `app.Run()` |
| `SpiritDeskWebHost.cs` | **注册服务 + 组装中间件管道** |

`Program.cs` 只有两行核心逻辑：

```csharp
var app = SpiritDesk.Web.SpiritDeskWebHost.Build(args);
app.Run();
```

所以答辩时说：

> 本项目的中间件管道在 `SpiritDeskWebHost.Build()` 里配置，不在 `Program.cs` 里展开写。

Shell 桌面版通过 `dotnet run` 启动同一个 `SpiritDesk.Web.dll`，走的也是这条管道。

---

## 1. 分两阶段：先注册服务，再组装管道

### 阶段 A：`WebApplication.CreateBuilder` → `builder.Services`

在 `var app = builder.Build()` **之前**，主要是 **依赖注入（DI）注册**，还不是中间件：

| 注册代码 | 作用 |
|----------|------|
| `AddRazorPages(...)` | Razor 页面 + 页面级授权约定 |
| `AddAuthentication(...).AddCookie(...)` | Cookie 登录能力（仅 `authEnabled` 时） |
| `AddAuthorization()` | 授权策略能力 |
| `AddDbContext<SpiritDeskDbContext>` | EF Core 数据库 |
| `AddScoped<SpiritDeskService>` | 业务服务 |
| `AddHttpContextAccessor()` | 让 Service 能读当前请求用户 |
| `AddHealthChecks()` | 健康检查 |
| `AddDataProtection()` | Cookie 加密密钥 |

### 阶段 B：`var app = builder.Build()` 之后 → `app.Use*` / `app.Map*`

这才是 **中间件管道**。

---

## 2. 本项目完整管道顺序

```text
1. UseExceptionHandler("/Error")
2. UseForwardedHeaders(...)
3. UseRouting()
4. UseStaticFiles()
5. UseAuthentication()        ← 仅 authEnabled = true
6. UseAuthorization()
7. MapRazorPages()
8. MapHealthChecks("/healthz")
9. MapGet / MapPost           ← /api/companion/*
```

对应代码位置：`SpiritDeskWebHost.cs` 约 132～257 行。

---

## 3. 逐段拆解

### 3.1 `UseExceptionHandler("/Error")`

```csharp
app.UseExceptionHandler("/Error");
```

| 项 | 说明 |
|----|------|
| 作用 | 后面任意中间件或页面抛未处理异常时，转到 `/Error` 页面 |
| 为什么靠前 | 尽量兜住整条管道里的异常 |
| 用户体验 | 避免直接显示黄页堆栈（生产环境尤其重要） |

---

### 3.2 `UseForwardedHeaders(...)`

```csharp
app.UseForwardedHeaders(new ForwardedHeadersOptions
{
    ForwardedHeaders = ForwardedHeaders.XForwardedFor | ForwardedHeaders.XForwardedProto
});
```

| 项 | 说明 |
|----|------|
| 作用 | 若前面有反向代理（Nginx、云负载均衡），正确识别真实客户端 IP 和 HTTPS |
| 本项目 | 本地 `127.0.0.1` 时常感觉不到；部署到服务器时更有用 |
| 答辩 | 属于“为部署预留”的中间件，不是业务核心 |

---

### 3.3 `UseRouting()`

```csharp
app.UseRouting();
```

| 项 | 说明 |
|----|------|
| 作用 | 启用端点路由：根据 URL 匹配 Razor Page 或 Minimal API |
| 和后面关系 | 后面的 `MapRazorPages`、`MapGet` 都依赖路由系统 |
| 记忆 | **先路由，再静态文件/认证** 是本项目采用的顺序 |

---

### 3.4 `UseStaticFiles()`

```csharp
app.UseStaticFiles();
```

| 项 | 说明 |
|----|------|
| 作用 | 从 `wwwroot` 直接返回 CSS、JS、图片、精灵立绘等 |
| 例子 | `/css/site.css`、`/assets/images/spirit-light.png` |
| 特点 | 匹配到文件时 often **短路**，不进入 Razor 页面 |
| 和 SSR | 页面 HTML 仍由 Razor 生成；样式脚本走静态文件中间件 |

详见 [08-wwwroot与静态资源详解.md](../08-wwwroot与静态资源详解.md)。

---

### 3.5 `UseAuthentication()`（条件启用）

```csharp
if (authEnabled)
{
    app.UseAuthentication();
}
```

`authEnabled` 来自配置 `SpiritDesk:Auth:Enabled`（开发环境 `appsettings.Development.json` 里常为 `true`）。

| 项 | 说明 |
|----|------|
| 作用 | 读取 `SpiritDesk.Auth` Cookie，解密验证，填充 `HttpContext.User` |
| 前置 | 启动时已 `AddAuthentication().AddCookie(...)` |
| 未开启时 | 不注册这层，本地演示可免登录访问页面 |
| 详见 | [auth/05-Cookie四个概念详解.md](../auth/05-Cookie四个概念详解.md) |

---

### 3.6 `UseAuthorization()`

```csharp
app.UseAuthorization();
```

| 项 | 说明 |
|----|------|
| 作用 | 检查当前请求是否满足授权要求 |
| 页面门禁 | `AddRazorPages` 里 `AuthorizeFolder("/")`：除登录/注册等外都要登录 |
| API 门禁 | `companionState.RequireAuthorization()` 等 |
| 必须在认证后 | 先 `UseAuthentication` 认人，再 `UseAuthorization` 判断是否放行 |

---

### 3.7 `MapRazorPages()`

```csharp
app.MapRazorPages();
```

| 项 | 说明 |
|----|------|
| 作用 | 把 URL 映射到 `Pages/` 下各 `.cshtml` 页面 |
| 例子 | `/Index`、`/Login`、`/Chat`、`/Settings` |
| 处理者 | 对应 `*.cshtml.cs` PageModel，再调 `SpiritDeskService` |
| 性质 | **端点**，不是“过道”中间件 |

---

### 3.8 `MapHealthChecks("/healthz")`

```csharp
app.MapHealthChecks("/healthz").AllowAnonymous();
```

| 项 | 说明 |
|----|------|
| 作用 | 健康检查接口，可探测站点和 SQLite 是否可用 |
| `AllowAnonymous` | 未登录也能访问，方便运维探测 |
| 答辩 | 属于运维友好端点，演示可不重点讲 |

---

### 3.9 Minimal API：`MapGet` / `MapPost`

```csharp
var companionState = app.MapGet("/api/companion/state", async (SpiritDeskService spiritDeskService) => { ... });
var companionSelect = app.MapPost("/api/companion/select-spirit", async (...) => { ... });
var companionCurrent = app.MapGet("/api/companion/current", async (...) => { ... });
```

| 路径 | 方法 | 谁调用 | 作用 |
|------|------|--------|------|
| `/api/companion/state` | GET | 浮球（可选） | 是否要选精灵、精灵列表 |
| `/api/companion/select-spirit` | POST | 浮球 | 切换精灵 |
| `/api/companion/current` | GET | 浮球轮询 | 当前精灵名、心情、立绘等 JSON |

开启 `authEnabled` 时：

```csharp
companionState.RequireAuthorization();
companionSelect.RequireAuthorization();
companionCurrent.RequireAuthorization();
```

浮球 `HttpClient` 需带与 WebView2 相同的 Cookie，见 [webview2/04-端口Cookie与本地Web子进程.md](../webview2/04-端口Cookie与本地Web子进程.md)。

## 4. 和 Razor 页面授权约定的关系

中间件只负责“检查”；**哪些页面要登录** 在 `AddRazorPages` 里提前声明：

```csharp
builder.Services.AddRazorPages(options =>
{
    if (authEnabled)
    {
        options.Conventions.AuthorizeFolder("/");
        options.Conventions.AllowAnonymousToPage("/Login");
        options.Conventions.AllowAnonymousToPage("/Register");
        options.Conventions.AllowAnonymousToPage("/Logout");
        options.Conventions.AllowAnonymousToPage("/Error");
        options.Conventions.AllowAnonymousToPage("/Privacy");
    }
});
```

流程：

```text
请求 /Index
  → UseAuthentication 解析 Cookie
  → UseAuthorization 发现 Index 需要登录
  → 未登录 → 302 到 /Login
```

## 6. 本项目没有单独写自定义中间件类

SpiritDesk **没有** 自己写 `public class MyMiddleware { ... }`，而是：

- 使用框架内置中间件（`UseStaticFiles`、`UseAuthentication` 等）
- 在 `SpiritDeskWebHost` 里 **组装顺序**
- 用 **授权约定** 和 **`RequireAuthorization()`** 控制访问

答辩可以说：

> 我们用的是 ASP.NET Core 标准中间件管道，通过配置组合完成异常处理、静态资源、Cookie 认证和 API 授权，没有额外手写 Middleware 类，结构清晰、适合课程项目规模。

## 7. 老师可能怎么问

**问：你们项目中间件配在哪？**  
> 在 `SpiritDeskWebHost.cs` 的 `Build` 方法里，`builder.Build()` 之后按顺序 `UseExceptionHandler`、`UseRouting`、`UseStaticFiles`，开启登录时还有 `UseAuthentication` 和 `UseAuthorization`，最后 `MapRazorPages` 和 Companion API。

**问：认证和授权中间件分别干什么？**  
> `UseAuthentication` 根据 Cookie 识别当前用户；`UseAuthorization` 判断该用户能否访问页面或 API，未登录会跳转登录页或返回未授权。

**问：静态资源和 Razor 页面谁先处理？**  
> 管道里先经过 `UseStaticFiles`，若是 wwwroot 下的文件会直接返回；否则继续往后，由 `MapRazorPages` 或 API 处理。

**问：浮球 API 怎么受保护？**  
> 开启门禁时对 `MapGet`/`MapPost` 端点调用 `RequireAuthorization()`，和网页共用同一套 Cookie 认证。
