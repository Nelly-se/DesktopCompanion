# 01 - 数据库基础知识

> 这篇先不讲代码，先讲看懂本项目数据库必须知道的基础词。

---

## 0. 一句话

**数据库就是专门存数据的地方。**  
本项目用的是 **SQLite**，它的特点是：一个 `.db` 文件就是一个数据库。

本项目默认数据库文件：

```text
data/spiritdesk.db
```

里面保存：

- 登录账号
- 用户档案
- 五精灵配置
- 待办任务
- 聊天记录
- 每日签到 / 投喂 / 游戏次数

---

## 1. 数据库、表、行、列

可以把数据库想象成一个 Excel 文件：

| 数据库概念 | Excel 类比 | 本项目例子 |
|------------|------------|------------|
| 数据库 | 一个 Excel 文件 | `spiritdesk.db` |
| 表 Table | 一个 Sheet | `Tasks`、`UserProfiles` |
| 行 Row | Sheet 里的一行数据 | 一条任务、一条聊天 |
| 列 Column | Sheet 里的一列字段 | `Title`、`CreatedAt` |

例如任务表可以理解为：

| Id | Title | IsCompleted | UserProfileId |
|----|-------|-------------|---------------|
| 1 | 完成实验报告 | false | 1 |
| 2 | 准备答辩展示 | false | 1 |

这就是一张表：每一行是一条任务，每一列是任务的一个属性。

---

## 2. 主键是什么？

**主键（Primary Key）** 是一张表里用来唯一识别每一行的字段。

通常叫：

```text
Id
```

例如 `Tasks` 表：

| Id | Title |
|----|-------|
| 1 | 完成实验报告 |
| 2 | 准备答辩展示 |

这里 `Id = 1` 和 `Id = 2` 就能区分两条任务。

答辩可以说：

> 主键是数据库表中每条记录的唯一标识，本项目大多数实体都使用 `Id` 作为主键。

---

## 3. 字段 / 列是什么？

字段就是表里的列。

例如 `WebAccounts` 表：

| 字段 | 含义 |
|------|------|
| `Id` | 账号记录编号 |
| `Username` | 用户名 |
| `PasswordHash` | 密码哈希 |
| `CreatedAt` | 创建时间 |

在 C# 里，这些字段通常对应实体类的属性：

```csharp
public string Username { get; set; } = string.Empty;
public string PasswordHash { get; set; } = string.Empty;
```

---

## 4. 索引是什么？

**索引（Index）** 可以理解成数据库的“目录”。

没有索引时，数据库可能要一行一行找。  
有索引时，数据库可以更快定位数据。

本项目里有这样的配置：

```csharp
entity.HasIndex(x => x.Username).IsUnique();
```

含义：

- 给 `Username` 建索引
- 并且要求它唯一
- 所以不能注册两个相同用户名

---

## 5. 唯一约束是什么？

**唯一约束** 表示某个字段不能重复。

例如 `WebAccounts.Username`：

| Username |
|----------|
| alice |
| bob |
| alice |

第三行如果再次出现 `alice`，就违反唯一约束。

本项目使用它防止重复注册同名账号。

---

## 6. 关系型数据库是什么？

SQLite 是关系型数据库。

“关系型”可以简单理解为：

> 数据按一张张表存储，表之间可以通过某些字段建立关系。

例如：

| 表 | 作用 |
|----|------|
| `UserProfiles` | 用户档案 |
| `Tasks` | 待办任务 |

`Tasks.UserProfileId` 可以指向 `UserProfiles.Id`，表示这条任务属于哪个用户档案。

本项目里任务、聊天、每日动作都通过 `UserProfileId` 归属到具体用户。

---

## 7. SQLite 是什么？

**SQLite 是轻量级数据库。**

它和大型数据库不同：

| 数据库 | 特点 |
|--------|------|
| SQLite | 一个文件就是一个库，适合本地、小项目、课程演示 |
| MySQL / PostgreSQL | 通常是独立数据库服务，适合多人、多服务、大规模系统 |

本项目选择 SQLite 的原因：

- 不需要单独安装数据库服务器
- 复制项目后容易运行
- 数据保存在本地 `.db` 文件里
- 适合桌面陪伴应用和课程答辩演示

---

## 8. 连接串是什么？

连接串就是告诉程序“数据库在哪里、怎么连”。

本项目默认连接串类似：

```text
Data Source=D:\...\data\spiritdesk.db
```

含义：

> 使用 SQLite，数据库文件路径是这个 `spiritdesk.db`。

代码中在 `SpiritDeskWebHost.cs` 里配置：

```csharp
optionsBuilder.UseSqlite($"Data Source={databasePath}")
```

## 9. EF Core 和数据库基础的关系

如果不用 EF Core，可能要手写 SQL：

```sql
SELECT * FROM Tasks WHERE IsCompleted = 0;
```

用了 EF Core 后，可以写 C#：

```csharp
var tasks = await dbContext.Tasks
    .Where(x => !x.IsCompleted)
    .ToListAsync();
```

EF Core 负责把 C# 查询翻译成 SQL。

所以：

| 你写的 | EF Core 做的 |
|--------|--------------|
| C# 实体类 | 推导表结构 |
| `DbSet` | 对应数据库表 |
| LINQ 查询 | 翻译成 SQL |
| `SaveChangesAsync()` | 提交 INSERT / UPDATE / DELETE |

## 11. 老师可能怎么问

**问：你们数据库是什么？**  
> 我们使用 SQLite，本地数据库文件默认是 `data/spiritdesk.db`。

**问：表、行、列怎么理解？**  
> 表是一类数据的集合，行是一条记录，列是这条记录的字段。比如 `Tasks` 表里一行就是一条任务。

**问：主键是什么？**  
> 主键是每条记录的唯一标识，本项目多数表使用 `Id` 作为主键。

**问：索引有什么用？**  
> 索引用来加快查询，也可以配合唯一约束防止重复数据，例如用户名唯一。

**问：为什么用 SQLite？**  
> SQLite 是单文件数据库，不需要额外数据库服务，适合本地桌面项目和课程演示。
