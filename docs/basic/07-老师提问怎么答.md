每题 **30 秒～1 分钟** 能说清即可；不会的细节诚实说「这块是队友负责的，我负责的是……」。

## 一、项目整体

**Q：你这个项目是什么？**  
A：SpiritDesk 是桌面精灵伴侣 Agent。用户选一个精灵，可以聊天、管任务、签到投喂。我们用 C# 做，分三层：Core 放数据模型，Web 做网页和业务和数据库，Shell 做 Windows 桌面窗口和桌面浮球。

**Q：为什么分三个项目？**  
A：Core 被 Web 引用，避免重复定义实体；Web 可以单独部署到服务器只跑网站；Shell 只负责桌面体验，业务还是 Web 那一套。

**Q：你们用的是 MVC 还是 MVVM？**  
A：网站是 **Razor Pages**（每页 `cshtml` + `PageModel`），思想接近 **MVC**，但没有 `Controllers` 文件夹；`Models/*ViewModel` 只是页面展示数据，**不是** MVVM 绑定。桌面 WPF 是**代码后置**，也没做标准 MVVM。详见 [09-MVC还是MVVM我们用的哪种.md](./09-MVC还是MVVM我们用的哪种.md)。

**Q：数据库用的什么？**  
A：**SQLite**，本地一个文件 `data/spiritdesk.db`，通过 **EF Core** 访问，适合课程演示，关机再开数据还在。详见 [13-EF是什么详解.md](./13-EF是什么详解.md)。

**Q：`spiritdesk.db` 为什么不进 Git？每人库不一样有问题吗？要不要 migration？**  
A：**不进 Git 是对的**——文件里是每人自己的任务/聊天等**数据**；**表结构**在 Git 的实体和 `SpiritDeskDbContext` 里。我们演示版用 `EnsureCreated` + 启动校验，没有 TypeORM 那种时间戳 migration 文件夹；产品化会改成 EF Migrations。详见 [14-数据库文件与迁移详解.md](./14-数据库文件与迁移详解.md)。

## 二、结构 / 文件夹

**Q：`src` 下面有什么？**  
A：三个子项目：`SpiritDesk.Core`、`SpiritDesk.Web`、`SpiritDesk.Shell`。Web 里 `Pages` 是页面，`Services` 是业务，`Data` 是数据库，`wwwroot` 是 CSS 和图片。

**Q：`wwwroot` 是什么？**  
A：网站静态资源目录，浏览器直接访问的图片、CSS、JS 都在这里，比如精灵 PNG 和 `site.css`。和 `Pages` 里 `.cshtml` 不同：cshtml 是服务器动态拼 HTML，wwwroot  是固定文件。详见 [08-wwwroot与静态资源详解.md](./08-wwwroot与静态资源详解.md)。

**Q：`wwwroot` 是怎么来的？是你自己写的吗？**  
A：**文件夹名和机制是 ASP.NET Core 规定的**（Web 项目模板自带，我们用 `UseStaticFiles()` 开放访问）。**不是**整个目录手写从零造出来的。里面分三种：`lib/` 是模板带的 Bootstrap、jQuery；**`css/site.css`、`js/site.js` 是我们团队写和维护的**；`assets/images/` 是 Figma 导出的 PNG。详见 [08-wwwroot §0](./08-wwwroot与静态资源详解.md#0-wwwroot-是怎么来的是不是我们自己写的)。

**Q：`.cshtml` 是干什么的？是不是 SSR？**  
A：是 **Razor 页面模板**，在**服务器**上执行 C#，把数据库数据填进 HTML 再返回浏览器，这叫 **SSR（服务端渲染）**。每个页一般一对文件：`Xxx.cshtml` 管界面，`Xxx.cshtml.cs` 管查库和表单。我们不是 React/Vue 那种纯前端 SPA。详见 [10-SpiritDesk.Web项目与cshtml详解.md](../10-SpiritDesk.Web项目与cshtml详解.md)。

**Q：`.csproj` 是干什么的？`SpiritDesk.Web.csproj` 呢？**  
A：`.csproj` 是**单个 C# 项目的工程文件**，写明目标框架、NuGet 包、项目引用、输出是类库/网站/exe。`SpiritDesk.Web.csproj` 用 `Sdk.Web`，编译出网站 DLL + Razor + wwwroot；Shell 引用它是为了内嵌同一套网站。详见 [12-csproj与obj文件夹详解.md](./12-csproj与obj文件夹详解.md)。

**Q：`obj` 文件夹干什么？`bin` 呢？要不要提交 Git？**  
A：`obj` 是编译**中间文件和缓存**；`bin` 是**最终 DLL/exe**。都是 `dotnet build` 自动生成，**不提交**，`.gitignore` 已忽略；删了再 build 会重新生成。详见 [12-csproj与obj文件夹详解.md](./12-csproj与obj文件夹详解.md)。

## 三、运行与演示

**Q：你怎么跑起来的？**  
A：答辩用 `.\run-shell.ps1` 启动桌面版，会自动拉起本地 Web。如果只演示网页，就 `dotnet run` Web 项目，浏览器打开 `http://localhost:5160`。

**Q：云端和本地有什么区别？**  
A：云端只部署 Web 到服务器；桌面浮球在自己电脑用 Shell。Shell 可以设环境变量连远程网址，也可以本地自带 Web。

## 四、你的个人分工（建议背熟）

**Q：你具体做了什么？**  
A：我主要负责三块：  
1. **美术**：在 Figma 设计五个精灵形象，导出 PNG 放到 `wwwroot/assets/images`。  
2. **账号**：完成登录、注册页面和表单提交逻辑，数据存 SQLite 的账号表。  
3. **界面**：统一薄荷绿主题，改 `site.css` 和页面布局，让登录按钮和全站风格一致。

**Q：登录是怎么实现的？**  
A：用 ASP.NET Core **Razor Pages**：`Login.cshtml` 出表单，`Login.cshtml.cs` 校验 **配置演示账号** 或 **SQLite `WebAccounts` 表**（密码 `IPasswordHasher` 哈希比对），成功 `SignInAsync` 写 **`SpiritDesk.Auth` Cookie**；`SpiritDeskWebHost` 在 `Auth.Enabled=true` 时全站 `AuthorizeFolder`。Shell **本地自启 Web** 会设环境变量关门禁；**连云端** 仍要在 WebView2 里登录，浮球用 `BuildAuthCookieHeaderAsync` 带 Cookie。详见 **[15-登录注册功能详解.md](./15-登录注册功能详解.md)**。

**Q：注册呢？密码存哪？**  
A：`Register.cshtml.cs` 校验用户名格式与重复 → `HashPassword` → EF 写入 `WebAccounts`，**明文不进库**。成功用 `TempData` 提示并跳转 `/Login`。

**Q：精灵图怎么用到程序里？**  
A：按精灵 ID 命名 PNG，放在静态资源目录，页面和浮球根据当前选的 ID 加载对应图片。

## 五、技术细节（浅答即可）

**Q：WPF 和 WebView2 是什么？**  
A：WPF 是 Windows 桌面 UI 框架；WebView2 是在窗口里嵌一个 Chromium 浏览器，显示我们的网页，这样桌面和网页共用一套界面。

**Q：EF / EF Core 是什么？**  
A：**Entity Framework Core**，.NET 的 ORM：实体类在 Core，DbContext 在 Web，把 `dbContext.Tasks.Add` 这类 C# 翻译成 SQL 读写 `spiritdesk.db`。详见 [13-EF是什么详解.md](./13-EF是什么详解.md)。

**Q：API 是什么？桌面浮球怎么换精灵？**  
A：Web 提供了 REST 接口，比如查询当前精灵、提交切换；浮球右键选名字后 POST 给 Web，Web 改数据库里的当前精灵字段。

**Q：AI 聊天怎么接的？**  
A：通过 `.env` 配置豆包（方舟）API Key，`LlmReplyService` 去请求；没配好或失败时用内置规则回复，保证答辩不断线。

## 六、边界题（需求文档里的「不做」）

**Q：为什么不做多用户 / RDS？**  
A：课程版本聚焦单用户演示和本地 SQLite，需求文档里明确这版不做多用户体系和云数据库迁移，避免范围失控。

**Q：登录算不算完整用户系统？**  
A：不算。这是可选的演示门禁，和电商级账号体系不是一回事，需求文档也写了不做登录鉴权重构。
