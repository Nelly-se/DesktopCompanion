# 16 - 数据访问层与对象关系映射详解

> 这篇专门解释答辩句子：  
> **“数据访问层使用 EF Core 进行对象关系映射。”**

读完要能讲清楚三件事：

1. **数据访问层** 是项目里负责读写数据库的那一层。
2. **对象关系映射（ORM）** 是把 C# 对象和数据库表互相转换。
3. 本项目用 **EF Core + SQLite**，通过 `SpiritDeskDbContext` 把实体类映射到 `spiritdesk.db`。

---

## 0. 一句话（先背）

**数据访问层使用 EF Core 进行对象关系映射**，意思是：  
项目不直接在页面里手写大量 SQL，而是把用户、任务、聊天、精灵这些数据定义成 **C# 实体类**；EF Core 根据这些类和 `DbContext` 配置，自动把它们对应到 SQLite 数据库中的表和字段。

答辩可以这样说：

> 我们的数据访问层主要由 `SpiritDeskDbContext` 和业务服务中的查询保存逻辑组成。EF Core 负责 ORM，把 `UserProfile`、`TaskItem`、`ChatMessage` 等 C# 实体映射成 SQLite 表，这样代码里可以用 LINQ 和对象操作数据库。

---

## 1. 数据访问层是什么？

### 1.1 先把项目分层看

```
页面 / API / Shell
        ↓
业务服务层 SpiritDeskService
        ↓
数据访问层 EF Core + SpiritDeskDbContext
        ↓
SQLite 数据库文件 spiritdesk.db
```

**数据访问层** 可以理解成“应用程序和数据库之间的中间层”。

它负责：

- 连接数据库
- 知道有哪些表
- 查询数据
- 新增、修改、删除数据
- 把修改保存到数据库文件

在本项目中，数据访问层的核心不是一个单独叫 `Repository` 的文件夹，而是由这些部分共同完成：

| 部分 | 文件 / 目录 | 作用 |
|------|-------------|------|
| 实体类 | `src/SpiritDesk.Core/Entities/` | 定义数据长什么样 |
| EF 上下文 | `src/SpiritDesk.Web/Data/SpiritDeskDbContext.cs` | 声明表、配置映射和种子数据 |
| 数据库注册 | `src/SpiritDesk.Web/SpiritDeskWebHost.cs` | 配置 SQLite 连接串，把 DbContext 注入系统 |
| 业务读写 | `src/SpiritDesk.Web/Services/SpiritDeskService.cs` | 调用 DbContext 查询和保存 |
| 登录注册读写 | `src/SpiritDesk.Web/Pages/Login.cshtml.cs`、`Register.cshtml.cs` | 查询账号、创建账号 |

---

## 2. 为什么不让页面直接操作数据库？

如果页面直接写 SQL，会出现几个问题：

1. 页面代码会变得很乱：既要管显示，又要管数据库。
2. SQL 字符串容易写错，字段名拼错运行时才发现。
3. 多个页面都写类似 SQL，后期改表结构很麻烦。
4. 登录、任务、聊天等逻辑难以复用。

所以项目把数据库访问集中到 **DbContext + Service** 中：

```
Index.cshtml.cs / Chat.cshtml.cs
        ↓ 调用
SpiritDeskService
        ↓ 使用
SpiritDeskDbContext
        ↓ EF Core 翻译
SQLite
```

这样页面只关心“我要展示什么”，业务服务关心“怎么处理业务”，数据访问层关心“怎么读写数据库”。

## 3. 对象关系映射（ORM）是什么？

ORM 的全称是 **Object Relational Mapping**，中文叫 **对象关系映射**。

拆开看：

| 词 | 含义 | 在本项目里 |
|----|------|------------|
| Object | 对象 | C# 里的 `UserProfile`、`TaskItem` 实例 |
| Relational | 关系型数据库 | SQLite 里的表、行、列 |
| Mapping | 映射 | EF Core 把类和表、属性和列对应起来 |

一句话：

> ORM 就是让程序员用“对象”的方式操作“关系型数据库”。

---

## 4. C# 对象和数据库表怎么对应？

以 `TaskItem` 为例，可以这样理解：

| C# 世界 | 数据库世界 |
|---------|------------|
| `TaskItem` 类 | `Tasks` 表 |
| 一个 `TaskItem` 对象 | `Tasks` 表中的一行 |
| `TaskItem.Title` 属性 | `Tasks` 表中的 `Title` 列 |
| `TaskItem.IsCompleted` 属性 | `Tasks` 表中的 `IsCompleted` 列 |

代码里写：

```csharp
dbContext.Tasks.Add(new TaskItem
{
    Title = "完成实验报告",
    IsCompleted = false
});

await dbContext.SaveChangesAsync();
```

EF Core 会在背后把它翻译成类似这样的数据库操作：

```sql
INSERT INTO Tasks (Title, IsCompleted, ...)
VALUES ('完成实验报告', 0, ...);
```

代码里查：

```csharp
var tasks = await dbContext.Tasks
    .Where(x => !x.IsCompleted)
    .ToListAsync();
```

EF Core 会把 LINQ 查询翻译成类似：

```sql
SELECT * FROM Tasks WHERE IsCompleted = 0;
```

所以我们写的是 **C# 对象和 LINQ**，真正执行的是 **SQL**。

## 5. 本项目的映射中心：SpiritDeskDbContext

文件：

```text
src/SpiritDesk.Web/Data/SpiritDeskDbContext.cs
```

它是 EF Core 的核心入口，主要做三件事。

### 5.1 声明有哪些表

```csharp
public DbSet<UserProfile> UserProfiles => Set<UserProfile>();
public DbSet<WebAccount> WebAccounts => Set<WebAccount>();
public DbSet<SpiritDefinition> Spirits => Set<SpiritDefinition>();
public DbSet<TaskItem> Tasks => Set<TaskItem>();
public DbSet<ChatMessage> ChatMessages => Set<ChatMessage>();
public DbSet<DailyActionLog> DailyActionLogs => Set<DailyActionLog>();
```

`DbSet<T>` 可以理解成“一张表在 C# 代码里的入口”。

| DbSet | 实体类 | 数据库含义 |
|-------|--------|------------|
| `UserProfiles` | `UserProfile` | 玩家档案 |
| `WebAccounts` | `WebAccount` | 登录账号 |
| `Spirits` | `SpiritDefinition` | 五精灵配置 |
| `Tasks` | `TaskItem` | 待办任务 |
| `ChatMessages` | `ChatMessage` | 聊天记录 |
| `DailyActionLogs` | `DailyActionLog` | 每日动作记录 |

### 5.2 配置表结构规则

`OnModelCreating` 里配置索引、主键、字段长度等规则，例如：

```csharp
modelBuilder.Entity<WebAccount>(entity =>
{
    entity.HasKey(x => x.Id);
    entity.HasIndex(x => x.Username).IsUnique();
    entity.Property(x => x.Username).HasMaxLength(64).IsRequired();
    entity.Property(x => x.PasswordHash).HasMaxLength(500).IsRequired();
});
```

含义：

- `Id` 是主键
- `Username` 建唯一索引，不能重复注册同名账号
- `Username` 最长 64
- `PasswordHash` 必填，最长 500

### 5.3 写入初始数据

`SpiritDefinition` 使用 `HasData(...)` 写入五精灵基础配置：

- 卷卷晴
- 嘻嘻滴
- 贴贴朵
- 慢慢壤
- 新新星

首次创建数据库时，EF Core 会按这些配置写入精灵初始数据。

## 6. 数据访问层的一次完整流程

以“进入首页加载工作台”为例：

```
浏览器访问首页
        ↓
Index.cshtml.cs
        ↓
调用 SpiritDeskService.BuildViewModelAsync
        ↓
SpiritDeskService 使用 dbContext 查询
        ↓
EF Core 把 LINQ 翻译成 SQL
        ↓
SQLite 返回数据
        ↓
EF Core 把表数据还原成 C# 对象
        ↓
组装 ViewModel 给页面显示
```

也就是说，用户看到的任务列表、当前精灵、金币、亲密度，不是页面凭空写死的，而是经过数据访问层从数据库读出来的。

## 7. 新增或修改数据时发生了什么？

以“切换当前精灵”为例，代码大致是：

```csharp
profile.CurrentSpiritId = spiritId;
dbContext.ChatMessages.Add(new ChatMessage
{
    Sender = "spirit",
    Content = "已切换精灵后的提示语"
});

await dbContext.SaveChangesAsync();
```

这里有两个关键点：

1. `profile.CurrentSpiritId = spiritId` 只是修改了 C# 对象。
2. `SaveChangesAsync()` 才会把变化真正写入 SQLite。

可以把 EF Core 理解成“先记录对象发生了什么变化，最后统一保存”。

## 8. Entity、DbSet、DbContext 的关系

这三个词答辩很容易混，按下面这样记：

| 名词 | 中文理解 | 例子 |
|------|----------|------|
| Entity | 实体类，一张表的数据结构 | `TaskItem` |
| DbSet | 某张表的操作入口 | `dbContext.Tasks` |
| DbContext | 数据库上下文，管理所有表和连接 | `SpiritDeskDbContext` |

关系图：

```
SpiritDeskDbContext
        ├── DbSet<UserProfile> UserProfiles
        ├── DbSet<TaskItem> Tasks
        ├── DbSet<ChatMessage> ChatMessages
        └── DbSet<SpiritDefinition> Spirits
```

一句话：

> Entity 描述表长什么样，DbSet 表示某张表，DbContext 管理整个数据库访问过程。

---

## 9. Entity 和 ViewModel 不一样

项目里还有 `Models` 目录，里面有很多 `ViewModel`，不要和 EF 的 Entity 混淆。

| 类型 | 位置 | 作用 | 是否直接对应数据库表 |
|------|------|------|----------------------|
| Entity | `SpiritDesk.Core/Entities/` | 持久化数据 | 是 |
| ViewModel | `SpiritDesk.Web/Models/` | 页面展示数据 | 不一定 |

例如：

- `TaskItem` 是 Entity，对应数据库里的任务表。
- `SpiritDeskViewModel` 是 ViewModel，用来把首页需要展示的数据一次性传给页面。

答辩可以说：

> Entity 是数据库模型，ViewModel 是页面展示模型。Service 会从多个 Entity 查询数据，再组装成 ViewModel 给 Razor 页面显示。

## 10. 本项目为什么适合用 EF Core？

本项目的数据规模不大，但数据类型比较多：

- 登录账号
- 用户档案
- 五精灵配置
- 待办任务
- 聊天记录
- 每日签到 / 投喂 / 游戏次数

用 EF Core 的好处：

1. 写 C# 类就能描述表结构，适合 .NET 项目。
2. 查询时用 LINQ，和 C# 语法一致。
3. 减少手写 SQL，降低字段名、表名拼错的概率。
4. 和 ASP.NET Core 依赖注入配合好，可以把 `DbContext` 注入到 PageModel 和 Service。
5. SQLite 是单文件数据库，方便课程演示和本地运行。

## 11. 老师可能怎么问

**问：什么叫数据访问层？**  
> 数据访问层就是负责和数据库交互的代码层。本项目里主要是 `SpiritDeskDbContext` 加上 Service 中使用 DbContext 的查询和保存逻辑。

**问：什么叫对象关系映射？**  
> 对象关系映射就是把 C# 对象和关系型数据库表对应起来。比如 `TaskItem` 类对应 `Tasks` 表，`Title` 属性对应 `Title` 字段。

**问：为什么使用 EF Core？**  
> 因为项目是 ASP.NET Core / .NET 9，EF Core 是 .NET 官方常用 ORM，可以用 C# 实体和 LINQ 操作 SQLite，减少手写 SQL。

**问：DbContext 是什么？**  
> DbContext 是 EF Core 访问数据库的入口，里面声明了 `DbSet`，并在 `OnModelCreating` 中配置主键、索引、字段长度和种子数据。

**问：SaveChangesAsync 有什么作用？**  
> 修改 C# 对象后，只有调用 `SaveChangesAsync()`，EF Core 才会把这些变化真正提交到数据库。

**问：Shell 桌面端会不会直接访问数据库？**  
> 不会。Shell 通过 WebView2 和 Web API 使用功能，真正访问 SQLite 的仍然是 Web 项目里的 EF Core 数据访问层。
