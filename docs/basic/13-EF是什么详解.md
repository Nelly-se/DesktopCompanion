## 0. 一句话（先背）

**EF（Entity Framework）= .NET 里用来操作数据库的「翻译官」**：  
你把数据定义成 **C# 类**，用 **C# 代码** 增删改查；EF 在幕后翻译成 **SQL**，读写 **SQLite 文件** `spiritdesk.db`。

**答辩**：我们不用手写大量 SQL，用 **EF Core + SQLite** 存用户、任务、聊天记录和五精灵配置。

---

## 1. 拆词：EF、EF Core、ORM、SQLite

| 词 | 全称 / 含义 | 在本项目里 |
|----|-------------|------------|
| **EF** | **E**ntity **F**ramework，微软的 .NET 数据库访问框架 | 口语里常泛指「用 EF 访问库」 |
| **EF Core** | Entity Framework **Core**，跨平台新版（.NET Core / .NET 5+） | 实际用的是这个；NuGet 包名里带 `EntityFrameworkCore` |
| **Entity（实体）** | 和数据库表对应的 C# 类 | `SpiritDesk.Core/Entities/*.cs`，如 `UserProfile`、`TaskItem` |
| **ORM** | **O**bject **R**elational **M**apping，对象 ↔ 关系表 的映射 | EF 就是一种 ORM |
| **DbContext** | 数据库「会话」：知道有哪些表、怎么连库 | `SpiritDesk.Web/Data/SpiritDeskDbContext.cs` |
| **DbSet** | 某一张表在代码里的入口 | 如 `dbContext.Tasks` 对应 `Tasks` 表 |
| **SQLite** | 轻量数据库，**一个文件就是一个库** | `data/spiritdesk.db`，适合课程演示 |

**EF 和 EF Core**：老师问「EF」时，答 **EF Core** 即可——本项目是 .NET 9，不会用已停更的旧版 EF 6（只跑在 .NET Framework 上那种）。

---

## 2. 没有 EF 时 vs 有 EF 时

### 2.1 没有 EF（手写 SQL）

登录后要查用户档案，你可能写成：

```sql
SELECT Id, Nickname, CurrentSpiritId, Mood FROM UserProfiles ORDER BY Id LIMIT 1;
```

在 C# 里还要自己：打开连接、执行命令、一行行读字段、拼成对象……

### 2.2 有 EF（本项目常见写法）

```csharp
var profile = await dbContext.UserProfiles.OrderBy(x => x.Id).FirstAsync();
// profile 已经是 UserProfile 对象，直接 profile.Nickname
```

EF 做的事：

1. 根据 `UserProfile` 这个类和 `DbContext` 的配置，知道表叫 `UserProfiles`、有哪些列  
2. 把 LINQ（`OrderBy`、`FirstAsync`）**翻译成 SQL**  
3. 执行 SQL，把结果**填回** `UserProfile` 实例  

**好处（答辩可提）**：少写 SQL、类型安全（拼错属性名编译期能发现）、换数据库时改连接方式即可（我们固定用 SQLite）。

## 3. EF 在本项目架构里的位置

```
浏览器 / Shell(WebView2)
        ↓ HTTP
Pages/*.cshtml.cs  或  Services/SpiritDeskService.cs
        ↓ 注入
SpiritDeskDbContext（EF）
        ↓ SQL
SQLite 文件  data/spiritdesk.db
```

| 层 | 目录 | 和 EF 的关系 |
|----|------|----------------|
| **实体定义** | `SpiritDesk.Core/Entities/` | 只描述「表长什么样」，**不引用 EF** |
| **映射与种子** | `SpiritDesk.Web/Data/SpiritDeskDbContext.cs` | 声明 `DbSet`、索引、五精灵 `HasData` |
| **业务读写** | `SpiritDesk.Web/Services/SpiritDeskService.cs` | `dbContext.Tasks.Add(...)`、`SaveChangesAsync()` |
| **页面直连库** | 如 `Login.cshtml.cs`、`Register.cshtml.cs` | 登录注册时查 `WebAccounts` |
| **启动注册** | `SpiritDeskWebHost.cs` | `AddDbContext<SpiritDeskDbContext>(... UseSqlite(...))` |

**记忆**：Core 里是 **POCO 类**（普通 C# 类）；Web 里用 **EF** 把这些类变成真正的表。

---

## 4. 对应哪些表？（和 Core 实体一一对应）

`SpiritDeskDbContext` 里的每个 `DbSet` ≈ SQLite 里一张表：

| DbSet（代码里） | 实体类 | 存什么 |
|-----------------|--------|--------|
| `UserProfiles` | `UserProfile` | 昵称、当前精灵、心情、亲密度、金币 |
| `WebAccounts` | `WebAccount` | 登录用户名、密码哈希 |
| `Spirits` | `SpiritDefinition` | 五精灵配置（名称、立绘路径、加成） |
| `Tasks` | `TaskItem` | 待办任务 |
| `ChatMessages` | `ChatMessage` | 聊天记录 |
| `DailyActionLogs` | `DailyActionLog` | 每日签到、投喂等次数 |

首次运行时会 `EnsureCreatedAsync()`：若 `spiritdesk.db` 不存在，EF 按实体和 `OnModelCreating` **建表**，并写入五精灵种子数据。

## 5. 三条真实代码链（看懂就够）

### 5.1 启动时：注册 EF + 指定 SQLite 文件

```csharp
// SpiritDeskWebHost.cs（节选）
builder.Services.AddDbContext<SpiritDeskDbContext>(optionsBuilder =>
    optionsBuilder.UseSqlite($"Data Source={databasePath}"));
```

含义：整个网站运行期间，需要数据库的地方可以 **注入** 一个 `SpiritDeskDbContext`，且连到 `data/spiritdesk.db`。

### 5.2 上下文：表集合 + 配置

```csharp
// SpiritDeskDbContext.cs（节选）
public DbSet<UserProfile> UserProfiles => Set<UserProfile>();
public DbSet<TaskItem> Tasks => Set<TaskItem>();
// OnModelCreating：用户名唯一索引、五精灵 HasData 种子……
```

### 5.3 业务：改对象 → 保存

```csharp
// SpiritDeskService.cs（典型模式）
profile.CurrentSpiritId = spiritId;
dbContext.ChatMessages.Add(new ChatMessage { ... });
await dbContext.SaveChangesAsync();
```

**要点**：改的是 C# 对象；**调用 `SaveChangesAsync()` 才真正写入文件**。

## 6. EF 和「网页 Models/ViewModel」别混了

| 名字 | 位置 | 作用 |
|------|------|------|
| **Entity** | `Core/Entities/` | 和 **数据库表** 对齐，给 EF 用 |
| **ViewModel** | `Web/Models/` | 给 **某一页展示** 用，不一定有对应表 |

例如 `SpiritDeskViewModel` 可能同时带「任务列表 + 当前精灵名 + 心情」，是从多张表 **查出来再拼** 的，不是 EF 直接映射的一张表。

**答辩**：Entity 是持久化模型；ViewModel 是页面用的展示模型，分工不同。

## 7. EF 和 API、Shell 的关系

- **网页**（Razor）：`SpiritDeskService` 通过 EF 读写库 → 返回 HTML。  
- **API**（`/api/companion/*`）：同样在 `SpiritDeskWebHost` / Service 里，最后还是 **EF 读 UserProfile、Spirits**。  
- **Shell 浮球**：不直接连 SQLite，而是 **HTTP 调 Web API**，由 Web 里的 EF 访问数据库。

```
浮球 → GET /api/companion/current → SpiritDeskService → EF → spiritdesk.db
```

所以：**数据库只在 Web 进程里通过 EF 打开**（桌面版也是 Shell 启动 Web 后走同一条路）。

---

## 8. 和 bin、NuGet 的关系

- `.csproj` 里有：`<PackageReference Include="Microsoft.EntityFrameworkCore.Sqlite" />`  
- `dotnet build` 后，EF 相关 DLL 会出现在 **`SpiritDesk.Web/bin/Debug/net9.0/`**（见 [12-csproj与obj文件夹详解.md](./12-csproj与obj文件夹详解.md)）。  
- **`spiritdesk.db` 不在 Git 里**，一般在运行目录下的 `data/`，属于运行产物（存的是**你的任务/聊天等数据**，不是表结构定义）。
- **表结构**由 Git 里的实体 + `SpiritDeskDbContext` 描述；本项目暂未使用 EF Migrations 文件夹，而用 `EnsureCreated` + 启动校验。详见 **[14-数据库文件与迁移详解.md](./14-数据库文件与迁移详解.md)**（与 TypeORM migration 对照）。

## 9. 老师可能怎么问

**问：EF 是什么？你们用的 EF 还是 EF Core？**  
> Entity Framework，.NET 的数据库 ORM。我们用的是 **EF Core**，配合 **SQLite**，在 Web 项目里通过 `SpiritDeskDbContext` 访问。

**问：为什么实体在 Core，DbContext 在 Web？**  
> Core 只放 **数据结构**，给 Web 和将来别的模块共用；**连库、映射、种子数据** 是 Web 启动时才需要的，所以 DbContext 放在 Web 的 `Data/`。

**问：和手写 SQL 比有什么优缺点？**  
> 优点：开发快、类型安全、改表结构可以跟 C# 类一起维护。缺点：复杂查询有时要调优；我们规模小，LINQ 够用。

**问：数据库文件在哪？**  
> 默认 `data/spiritdesk.db`，连接串在 `SpiritDeskWebHost` 里配置，可用 `appsettings.json` 覆盖。

**问：登录表和游戏档案为什么两张表？**  
> `WebAccounts` 管账号密码；`UserProfile` 管养成进度。现在通过 `AccountUsername` 绑定登录账号，并用 `UserProfileId` 隔离任务、聊天和每日互动数据，详见 [03-CSharp-数据层与EF-Core.md](../03-CSharp-数据层与EF-Core.md) §7。
