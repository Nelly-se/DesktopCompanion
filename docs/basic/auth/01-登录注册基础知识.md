# 01 - 登录注册基础知识

本文不讲 SpiritDesk 具体代码，只讲「登录 / 注册」在 Web 应用里通常是什么意思。

## 1. 注册是什么

**注册** = 用户在系统里**第一次创建账号**。

用户一般会提供：

- 用户名（或邮箱、手机号）
- 密码
- 有时还有确认密码、昵称等

系统收到后要做的事：

1. 检查用户名是否已被占用；
2. 检查密码格式是否合法；
3. **不要把明文密码直接存进数据库**；
4. 把账号信息写入数据库；
5. 可选：自动登录，或跳转到登录页让用户再登一次。

## 2. 登录是什么

**登录** = 用户证明自己「就是之前注册过的那个人」。

常见做法：

- 用户输入用户名 + 密码；
- 系统在数据库里找到这个用户；
- 对比密码是否正确；
- 正确 → 认为「已登录」，允许访问需要身份的功能；
- 错误 → 提示用户名或密码错误。

登录成功后，系统需要**记住当前是谁在使用**，否则用户每点一个链接都要重新输密码。

## 3. 密码为什么不能明文存库

如果数据库里直接存 `password = "123456"`：

- 数据库文件泄露 → 所有用户密码立刻暴露；
- 管理员也能看到用户真实密码。

正确做法是存 **密码哈希（Password Hash）**：

```text
用户输入: spiritdesk
        ↓
哈希算法（加盐）
        ↓
数据库里存: AQAAAAEAACcQ...（一长串乱码）
```

登录时再对用户输入的密码做同样哈希，和库里的哈希比对，**相等则密码正确**。

SpiritDesk 用的是 ASP.NET Core 自带的 `IPasswordHasher<WebAccount>`，属于成熟做法。

## 4. Cookie 是什么（本项目用的方式）

**Cookie** 是浏览器（或 WebView2）保存的一小段文本，之后访问同一网站时会**自动带上**。

登录成功后，服务器可以回复：

```http
Set-Cookie: SpiritDesk.Auth=加密后的身份信息; HttpOnly; ...
```

下次请求会自动带上：

```http
Cookie: SpiritDesk.Auth=...
```

服务器解密/验证这个 Cookie，就知道「当前用户是谁」。

| 特点 | 说明 |
|------|------|
| 存在哪 | 浏览器 / WebView2 本地 |
| 谁签发 | 服务器（ASP.NET Core 认证中间件） |
| 有效期 | 可设置，本项目约 12 小时滑动过期 |
| HttpOnly | JS 读不到，略防 XSS 偷 Cookie |

> 上面四行若看不懂，请读专篇：[05-Cookie四个概念详解.md](./05-Cookie四个概念详解.md)（含解密验证、存储位置、签发者、12 小时滑动过期、HttpOnly 与 XSS）。

## 5. Session 和 Cookie 的区别（了解即可）

| | Cookie 方案 | Session 方案 |
|---|-------------|--------------|
| 状态存在哪 | 客户端 Cookie 里带令牌 | 服务器内存/Redis 存 sessionId |
| 客户端带什么 | Cookie 值 | 通常是 SessionId Cookie |
| 本项目 | ✅ Cookie 认证 | ❌ 未用经典 Session |

答辩时可以说：本项目用 **Cookie Authentication**，由 ASP.NET Core 统一管理登录状态。

## 6. 什么是「登录门禁」

**门禁** = 未登录用户不能访问某些页面。

例如：

- 未登录访问 `/Index` → 自动跳转到 `/Login`；
- 已登录 → 正常看首页、聊天、设置。

实现方式通常是：

1. 在启动时注册认证中间件（`UseAuthentication`）；
2. 给页面或文件夹标记「需要登录」（`Authorize`）；
3. 少数页面允许匿名（`AllowAnonymous`），如 `/Login`、`/Register`。

SpiritDesk 用配置项 `SpiritDesk:Auth:Enabled` 控制门禁开或关。

## 7. 账号数据和业务数据为什么要分开

很多项目会把两类数据分开：

| 类型 | 存什么 | 例子 |
|------|--------|------|
| **认证账号** | 用户名、密码哈希、注册时间 | `WebAccounts` 表 |
| **业务档案** | 昵称、等级、任务、聊天记录 | `UserProfiles` 表 |

原因：

- 登录逻辑只关心「密码对不对」；
- 游戏/养成逻辑关心「精灵、任务、金币」；
- 分开后结构清晰，以后改业务字段不影响登录表。

SpiritDesk 用字段 **`AccountUsername`** 把两边绑在一起（同一规范化用户名）。

## 8. 注册 / 登录 / 登出 三句话

| 操作 | 做什么 |
|------|--------|
| **注册** | 往数据库写新账号（+ 可选创建业务档案） |
| **登录** | 校验密码 → 服务器签发 Cookie |
| **登出** | 清除 Cookie → 下次请求视为未登录 |

## 9. 和老师对话时的基础说法

> 注册是把用户名和密码哈希写入数据库；登录是校验密码后由服务器签发 Cookie；后续请求靠 Cookie 识别用户。密码不明文存储，用的是框架提供的 PasswordHasher。
