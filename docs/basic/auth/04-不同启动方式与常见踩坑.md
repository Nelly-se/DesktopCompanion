# 04 - 不同启动方式与常见踩坑

本文解释：为什么换一种方式运行，登录注册表现会不一样；以及「注册了下次没了」通常是什么原因。

## 1. 三种常见启动方式

| 脚本 / 方式 | 跑什么 | 登录注册页 | 数据库大致位置 |
|-------------|--------|------------|----------------|
| `run-shell.ps1` | WPF 桌面 + 本地 Web 子进程 | **默认没有** | `SpiritDesk.Web/bin/Release/net9.0/data/` |
| `run-shell-with-auth.ps1` | 同上，但开门禁 | **有** | 同上 Release |
| `run-web.ps1` | 只跑 Web | **有** | `SpiritDesk.Web/bin/Debug/net9.0/data/` |

**同一份代码，不同配置 + 不同 db 路径 = 不同体验。**

## 2. 为什么 run-shell 看不到登录页

`MainWindow` 启动 Web 子进程时：

```csharp
startInfo.Environment["ASPNETCORE_ENVIRONMENT"] = "Development";
if (!IsShellAuthRequired())
{
    startInfo.Environment["SpiritDesk__Auth__Enabled"] = "false";
}
```

环境变量 `SpiritDesk__Auth__Enabled=false` 会**覆盖** `appsettings.Development.json` 里的 `Enabled: true`。

结果：

- 访问 `/Login`、`/Register` 会被重定向到首页；
- 全站免登录；
- 使用 **无账号绑定的默认 `UserProfile`**。

要演示登录注册，请用：

```powershell
.\run-shell-with-auth.ps1
```

或设置：

```powershell
$env:SPIRITDESK_REQUIRE_AUTH = "1"
```

## 3. Debug 和 Release 各有一份数据库

| 构建 | Web DLL 目录 | 数据库 |
|------|--------------|--------|
| Debug | `bin/Debug/net9.0/` | `.../data/spiritdesk.db` |
| Release | `bin/Release/net9.0/` | `.../data/spiritdesk.db` |

在 `run-web`（Debug）里注册的用户，**不会自动出现在** `run-shell`（Release）读的那份库里。

**建议**：答辩演示登录注册时，固定用一种脚本，不要混用。

## 4. 每次桌面启动端口可能不同

Shell 本地模式：

```csharp
var port = GetFreePort();
return $"http://127.0.0.1:{port}";
```

Cookie 按 **主机 + 端口** 区分。

- 上次：`http://127.0.0.1:5188` 登录；
- 这次：`http://127.0.0.1:52401` 启动；

→ 浏览器/WebView2 **不会带上旧 Cookie**，需要**重新登录**。

注意：**账号仍在数据库里**，只是「登录状态」没了，不是注册被删。

## 5. 数据库被重置时账号会真没了

`DatabaseBootstrapper` 发现表结构不兼容时，会备份并删除 `spiritdesk.db`，EF 再建新库。

控制台可能出现：

```text
[SpiritDesk] Reset local database: ... Backup saved to spiritdesk.backup-....db
```

此时 `WebAccounts` 里注册的用户会随旧库一起被移走（旧库在 backup 文件里可找回）。

## 6. 现象对照表

| 你看到的现象 | 最可能原因 |
|--------------|------------|
| 没有登录/注册页 | `run-shell.ps1` 关了门禁 |
| 像「默认用户」，任务聊天是演示数据 | 门禁关，用的是 `AccountUsername == null` 档案 |
| 注册后换 run-shell 没了 | 读的是 Release 的 db，注册写在 Debug 的 db |
| 关掉再开要重新登录 | 端口变了，Cookie 不共用 |
| 账号真的查不到了 | 库被 Bootstrapper 重置，或删了 `data` 文件夹 |

## 7. 自检步骤

1. 确认启动脚本（是否要 `run-shell-with-auth`）；
2. 找到当前使用的 `spiritdesk.db` 完整路径；
3. 用 DB Browser 打开，查 `WebAccounts` 是否有你的用户名；
4. 查 `UserProfiles` 是否有相同 `AccountUsername`；
5. 看启动日志是否有 `Reset local database`。

## 8. 答辩怎么说

> 项目支持可配置 Cookie 门禁。本地 Shell 默认关闭登录方便一体演示；需要讲注册登录时用 `run-shell-with-auth` 或单独跑 Web。账号在 SQLite 的 WebAccounts 表，业务档案在 UserProfiles，通过 AccountUsername 关联。不同构建输出目录下各有 spiritdesk.db，混用启动方式会看起来像数据丢失，实际是读的不是同一份库。
